# 实例：RSNA Knee v5 标签导入与训练对比

本例基于实际完成的本地实验，2026-09-21 整理。适合学习“拿到外部标签后怎么检查、接入、比较和解释”。它不是从原始报告重新生成 v5 的完整复现。

**真实部分**：数据规模、字段、文件哈希和下文实验汇总。
**虚构部分**：`DEMO_*` 编号及其演示数值，仅用于解释接口和算术，没有对应真实病例。不发布原始标签表、病例 UID、报告原文或影像。

## 1. 输入是什么

输入为 [yunusgmsoy 的四来源合并标签](https://www.kaggle.com/datasets/yunusgmsoy/rsna-knee-llm-labels-4-source-merged)中的 `report_labels_v5.csv`。本例核查的版本：

- 4,407 个唯一研究，25 列。
- 一列 `StudyInstanceUID`；每个标签各有一个分数列和一个 `__conf` 列。
- SHA256：`16cf44a89e027c80ff9b1a69e1ac6713d1f6da1765b3748c01f6ae91827ef167`。
- 12 个标签按顺序为：`ACL`、`MCL`、`Medial Meniscus`、`Lateral Meniscus`、`Medial OA`、`Lateral OA`、`PF OA`、`Effusion`、`Synovitis`、`Baker's`、`Contusion`、`Fracture`。

文件可能更新；重用时重新记录哈希。列名相同不代表版本相同。

以下只展示两类字段的**虚构片段**，不是完整的 25 列文件，也不能直接送进本项目训练器：

```csv
StudyInstanceUID,ACL,ACL__conf,Effusion,Effusion__conf
DEMO_A,0.80,0.90,0.20,0.60
DEMO_B,0.10,0.85,0.70,0.40
```

`ACL=0.80` 是训练软目标；`ACL__conf=0.90` 是本次选择使用的损失权重。不能把它们解释为临床患病概率 80% 和判断正确率 90%。v5 的置信度生成公式仍不明。

## 2. 先检查，再决定哪些行可以训练

1. 检查唯一 ID、12 类字段、缺失、有限值和 [0,1] 范围。
2. 按 ID 对齐项目 manifest，而不是依赖 CSV 行号。
3. 保留本次确定的全部 3,862 个训练候选；其他分组不得因存在于 v5 表中就进入训练。
4. 保护官方 58 例、独立复核集及隔离病例；检查患者/重复影像跨组问题。
5. 旧标签、原始 v5、划分及输入缓存保持不变；新方案另存版本。

完整 CSV 的 4,407 行不等于本次可训练的 3,862 行。这个差别由实验划分决定，不是根据标签好坏临时筛选。

## 3. 导入既有 v5：不重新计算其分数

本次经明确选择的导入政策是：对有效且属于训练候选的单元格，令 `target=v5 分数`、`weight=__conf`、`mask=1`。缺失或非有限值必须单独处理，不能默认为阴性。

对虚构的 DEMO_A/ACL：

```text
target = 0.80
weight = 0.90
mask = 1
单项损失贡献 = 0.90 × BCE(模型预测, 0.80)
```

此式只演示单项加权；整个批次如何归一化由所用训练器决定，重现实验需保持一致。如果病例属于保护组，就不能通过设置 mask=1 将它纳入训练。

这条导入路径沿用外部表已有的缺失和权重政策，不代表已经验证其合理性。它与本技能默认的“按原文证据融合新来源”路径不同。

## 4. 公式演示：仅针对双来源前身

假设两个来源在同一项给出 P=0.9、S=0.1：

```text
score = (0.9 + 0.1) / 2 = 0.5
confidence = 1 - abs(0.9 - 0.1) = 0.2
```

分歧很大，所以结果折中、训练权重低。如果 P=S=0.5，公式却给 confidence=1；来源的 0.5 若表示未提及，这只是“一致地缺证据”，不是确诊。

滑膜炎演示：P=0.6、S=0.2，初始 score=0.4、confidence=0.6；若合并积液分数为 0.3，则最终滑膜炎分数是 `min(0.4, 0.8×0.3)=0.24`，权重仍为 0.6。

这些是虚构数值，但演示的前身规则已在 51,433 个纳入核查的真实单元格上匹配。范围、排除条件与来源见[前身公式核查](kaggle-predecessor-formula.md)。**不使用这套公式重新计算 v5，也不把它当成 v5 的生成方法。**

## 5. 实际完成的训练对比

| 项目 | 本次固定条件 |
|---|---|
| 训练成员 | 两组均为 3,862 例 |
| 模型与输入 | 相同预训练 ResNet18，三平面 224×224 缓存 |
| 训练预算 | 每组每种子 3 轮；种子 42、43、44 |
| 其他控制 | 相同初始化、优化器、学习率、批次顺序和最终轮模型选择 |
| 开发参考 | 冻结的 196 例 AI 报告复核；各类有效评价样本数不同 |
| 旧组 | 本地 data_v4 four_state，保留 target/weight/mask |
| 新组 | v5 分数作为 target，__conf 作为 weight，有效训练项 mask=1 |

这是**整个监督方案的比较**：分数、监督覆盖和权重同时变化。不能把提高单独归因于某个模型、置信权重或四源融合。

| 种子 | 旧组宏平均 AUC | v5 宏平均 AUC | 差值 |
|---|---:|---:|---:|
| 42 | 0.758451 | 0.786442 | +0.027991 |
| 43 | 0.745025 | 0.822214 | +0.077190 |
| 44 | 0.753215 | 0.768764 | +0.015549 |
| 平均 | 0.752230 | 0.792473 | +0.040243 |

逐类三种子平均：

| 类别 | 参考阳性/阴性数 | 旧 AUC | v5 AUC |
|---|---:|---:|---:|
| ACL | 23/156 | 0.722408 | 0.772947 |
| MCL | 2/173 | 0.748555 | 0.707129 |
| Medial Meniscus | 77/104 | 0.675283 | 0.708208 |
| Lateral Meniscus | 34/140 | 0.702241 | 0.645308 |
| Medial OA | 14/112 | 0.699830 | 0.830782 |
| Lateral OA | 1/123 | 0.962060 | 0.970190 |
| PF OA | 10/112 | 0.613095 | 0.692857 |
| Effusion | 28/125 | 0.847619 | 0.889143 |
| Synovitis | 22/6 | 0.929293 | 0.931818 |
| Baker's | 10/96 | 0.838542 | 0.849306 |
| Contusion | 16/112 | 0.602121 | 0.805246 |
| Fracture | 14/120 | 0.685714 | 0.706746 |

10 类均值提高，MCL 和 Lateral Meniscus 下降。Lateral OA 仅一个参考阳性；去掉它后，其余 11 类平均差值为 +0.043163。三个种子并不能证明统计显著或临床泛化。

小批量验证后完成全部六次训练；六个最终 checkpoint 均重新加载并复现首个完整开发批次，AUC 通过独立排序计算复核，原始输入和缓存哈希保持一致。这里不声称重新推理了整个开发集来核验 checkpoint。

**准确结论**：在本次三轮训练和既有 AI 开发参考下，v5 监督方案的平均指标更好。`physician_validated=false`；没有使用官方 58 例或独立医生/MRI 金标准计算本次成绩，也没有自动替换默认模型。

## 6. 复用此例时交付什么

- 私有运行目录保存输入哈希、来源与版本、成员划分、target/weight/mask 和实验协议。
- 输出逐种子及逐类指标、有效样本量、checkpoint 核查和局限说明。
- 公开文档只保留经过审核的汇总；病例级产物留在授权环境。
- 本例数据依据本地 `protocol.json`、`summary.json`、`训练对比报告.md` 和公式核查结果整理。这些实验产物及图像未随技能分发，读者不能仅靠技能仓库复跑相同指标。

可用提示词：

```text
使用 $report-label-ensemble，参考 rsna-v5-worked-example，检查我当前选定的标签表。
先核实版本、字段和训练划分；复用现有训练器，固定其他实验条件做配对比较。
分别说明哪些结果已实测、哪些只是公式演示，以及评价参考是否由医生确认。
```

最通俗的解释：先看“新答案表”能否对上病例，再让同一个学生用旧答案、新答案各学同样长的时间，最后用同一套参考评分。这里新答案总体更有帮助，但参考本身也是 AI 整理的，所以还不能说它已经通过医生验证。
